# 业务桌面零占位助手与左下角设置设计

日期：2026-07-22

## 背景与问题

上一轮将收起态助手从底部整行安全区改为右侧 124dp 控制列，但该控制列仍持续压缩业务表单。顶部为了只承载“设置”又保留了 52dp Compose 工具栏，形成了额外空白层。用户要求保持左右业务布局，同时消除这两块无效占位。

根因已经定位：

- `BusinessDesktopLayoutPolicy.collapsedAssistantWidth` 固定为 124dp，收起态仍从业务区扣除宽度。
- `BusinessDesktopShell` 在收起态把吉祥物放进该固定宽度控制列。
- `BusinessTopNavigation` 单独占用 52dp，仅渲染右侧“设置”。
- `BusinessSidebar` 没有底部操作区，设置只能依赖顶部工具栏。

## 目标

- 助手收起时不预留任何横向布局宽度，业务区获得左侧导航以外的全部宽度。
- 吉祥物保留在业务区右下角，只有吉祥物自身是悬浮点击目标，不生成整条背景栏。
- 助手展开后继续使用右侧相邻停靠布局，支持拖动宽度和收起，不覆盖业务表单。
- 删除 Compose 顶部工具栏及其 52dp 高度。
- 设置入口固定在左侧导航底部，与顶部三个业务入口分区展示。
- 保持业务页面与 Provider 编辑对话框在助手展开/收起过程中的 Compose 状态。

## 方案比较

### 方案 A：零宽收起态 + 右下角悬浮吉祥物（采用）

收起时布局策略返回 `businessWidth = availableWidth`、`assistantWidth = 0dp`。Shell 使用同一业务内容容器，并在其上层 `Box` 的右下角绘制吉祥物。展开时才渲染分隔条与助手面板。

优点：消除整条右侧占位；保留用户指定的右下角入口；展开仍是相邻分栏。代价：吉祥物自身会覆盖右下角很小的视觉区域，但不会产生背景栏或扣减业务宽度。

### 方案 B：吉祥物移入左侧栏

完全不覆盖业务区，但违背用户要求的右下角助手入口，且会让设置与助手两个底部动作竞争空间。

### 方案 C：缩窄右侧控制列

实现简单，但仍然永久占用业务宽度，不能解决本次反馈的根因。

## 组件设计

### `BusinessDesktopLayoutPolicy`

- 删除 `collapsedAssistantWidth` 常量。
- 收起布局始终返回零宽助手和完整业务宽度。
- 展开阈值仍由最小业务宽度、分隔条和最小助手宽度组成，不因收起态变化。
- 非法、负数和超大宽度继续沿用现有归一化规则。

### `BusinessDesktopShell`

- 删除外层 `Column` 中的 `BusinessTopNavigation`。
- 主体直接使用全高 `Row`：左侧固定导航，右侧业务与助手停靠区域。
- 业务内容保持单一组合位置。
- 收起时不再渲染 `COLLAPSED_ASSISTANT_CONTROL` 容器；在停靠区域最上层 `Box` 右下角直接绘制吉祥物。
- 宽度不足提示改为紧邻吉祥物上方的局部浮动文本，不创建背景栏。
- 展开时沿用现有相邻 Row、助手面板和拖动分隔条。

### `BusinessSidebar`

- 顶部继续展示“业务导航”和工作台、资料录入、运行记录。
- 使用弹性 `Spacer` 将设置入口推到左下角。
- 设置入口复用统一的目的地回调与 Tab 语义，选中设置页时高亮。
- 新增独立语义标签，避免与已删除的顶部入口选择器混淆。
- 侧栏暴露真实组合完成回调，供安装包烟测确认新的主导航已经进入已提交帧。

### `BusinessTopNavigation`

- Shell 不再组合该组件。
- 删除已无生产用途的组件和对应测试，避免留下不可达 UI 与重复导航真相。
- 原生 Windows 标题栏继续作为唯一品牌与窗口顶部区域。

### 安装包烟测契约

- 现有 `topNavigationComposed` 不能在删除组件后继续保留或伪造为 `true`。
- 将窗口组合信号、readiness、JSON 报告和 PowerShell 断言统一迁移为 `sidebarNavigationComposed`。
- `Main.kt` 把该信号连接到 `BusinessSidebar` 的真实组合完成回调。
- 安装包烟测继续同时要求 window、shell、侧栏导航、品牌 Logo 和吉祥物均真实完成。

## 状态与交互

1. 初始收起：业务区占满左侧导航右边的全部宽度，吉祥物悬浮在右下角。
2. 点击吉祥物：宽度足够时打开右侧助手，业务区按相邻分栏缩小；宽度不足时仅在吉祥物上方显示提示。
3. 拖动分隔条：继续在现有 360dp 到动态最大值范围内调整助手宽度。
4. 点击助手内吉祥物：助手收起，业务区立即恢复全部宽度，右下角悬浮入口重新出现。
5. 点击左下角设置：进入 Provider 设置页；左侧设置入口高亮。点击任一业务入口返回对应页面。

## 测试策略

- 布局策略测试：收起态 `assistantWidth == 0dp`，业务宽度等于全部可用宽度，极端输入仍守恒。
- 侧栏测试：设置位于三个业务入口之后并接近侧栏底部；四个入口都具有唯一标签、点击回调和正确选中语义。
- Shell 测试：不再存在顶部工具栏和右侧收起控制列；业务区覆盖全部停靠宽度；吉祥物边界位于业务区右下角；展开、拖动、收起和 Provider 编辑状态保持继续通过。
- 安装包烟测测试：旧 `topNavigationComposed` 字段和断言完全消失，新 `sidebarNavigationComposed` 必须来自真实侧栏组合。
- 真实窗口测试：最大化后确认无顶部空白工具栏、无右侧灰色占位条、设置在左下角且可进入/退出设置页、展开助手为相邻分栏。

## 非目标

- 不修改助手面板内部会话、附件或 Provider 协议。
- 不修改原生标题栏品牌与窗口控制。
- 不改变左侧导航宽度、展开助手最小/最大宽度或审批行为。
- 不处理与本次界面无关的 action runtime 快速终态竞态。
