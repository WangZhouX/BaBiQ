# Business Backend 残留开发会话恢复设计

## 问题

IDEA 停止 `Business Backend（后端）` 时可能直接终止 Gradle/Java 进程树，导致 JVM shutdown hook
没有完成 `development-session.json` 删除。当前 runner 只判断文件是否存在，因此后端已经退出、
49391 端口已经释放时，后续启动仍误报已有后端并以 exit code 1 结束。

## 方案比较

1. **无条件删除会话文件**：简单，但可能删除仍在运行的真实后端会话，拒绝。
2. **按文件时间或 PID 判断**：TTL 会误判长时间运行的后端；PID 会复用且需要改变协议，拒绝。
3. **认证探测 + 端口空闲双重确认**：先用会话中的一次性身份探测真实 WebSocket；探测失败后还要
   确认固定 loopback 端口可绑定，两个条件同时成立才回收会话文件。采用此方案。

## 设计

- `BusinessBackendDevelopmentRunner.start()` 在创建 KeyStore 和新 child 前执行残留会话恢复。
- 会话可被真实认证：保留文件并拒绝重复启动。
- 会话无法认证但端口仍被占用：保留文件并报告端口占用，避免误删活跃或未知服务。
- 会话无法认证且端口空闲：验证会话文件在探测期间没有被替换，安全删除后继续启动。
- 会话文件损坏但端口空闲：同样允许回收；符号链接、reparse point 或探测期间被替换仍快速失败。
- 正常关闭仍由现有 lease 删除文件；自动恢复只处理异常终止残留，不影响安装包 embedded 模式。
- 诊断只输出固定错误，不记录会话路径、token 或原始认证异常。

## 测试

- 残留有效会话、认证失败、端口空闲时自动回收并发布新会话。
- 会话仍可认证时拒绝重复启动且不调用 child launcher。
- 认证失败但端口占用时拒绝启动且保留会话。
- 损坏会话且端口空闲时回收；文件被替换时拒绝删除。
- 运行 runner 定向测试、app runtime/composition 相关测试和业务桌面全量测试。
