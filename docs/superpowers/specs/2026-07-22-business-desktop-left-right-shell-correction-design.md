# 业务桌面左右壳层纠偏设计

## 背景

当前翔鸟律智桌面端把品牌、工作台、资料录入、运行记录和设置全部放入应用内容区顶部，并在助手收起时为右下角吉祥物保留一条横跨窗口、固定 124dp 高的底部区域。真实最大化窗口截图证明这会产生三个问题：

1. 吉祥物没有展开时，整条底部空间仍被占用，业务表单的底部操作被挤出或遮挡。
2. 工作台、资料录入、运行记录被错误迁移到顶部，破坏原有左右布局。
3. Windows 原生标题栏已经显示产品 Logo 和“翔鸟律智桌面端”，应用内容区又重复显示同一品牌。

## 目标布局

窗口继续使用 Windows 原生标题栏，标题栏是唯一显示产品 Logo 和“翔鸟律智桌面端”的位置，并继续提供最小化、还原/最大化和关闭按钮。

原生标题栏下方保留一条 52dp 高的轻量顶部工具栏。工具栏不再渲染 Logo、产品名和业务一级导航，只在右侧提供“设置”入口。

工具栏下方采用稳定的水平布局：

```text
┌──────────── Windows 原生标题栏：唯一 Logo + 产品名 ────────────┐
├──────────────────────── 顶部工具栏：设置 ────────────────────────┤
├──────────┬──────────────────────────────┬──────────────────────────┤
│ 左侧导航 │           业务内容区          │ 收起控制区 / 助手面板     │
│ 工作台   │                              │ 收起：右下角吉祥物        │
│ 资料录入 │                              │ 展开：可调宽助手           │
│ 运行记录 │                              │                          │
└──────────┴──────────────────────────────┴──────────────────────────┘
```

## 导航规则

- 左侧导航恢复“业务导航”以及工作台、资料录入、运行记录三个目的地。
- 左侧导航固定为 210dp；当前窗口最小宽度为 1100dp，因此收起状态仍至少为业务区保留 766dp。
- 设置不出现在左侧，只能从顶部工具栏进入。
- 继续使用现有 `BusinessDesktopDestination` 作为唯一导航状态，不复制第二份路由状态。
- 当设置页打开时，左侧三个业务入口都不显示选中；点击任一业务入口即可离开设置页。

## 助手收起与展开

- 收起状态删除整条 124dp 底部安全区。
- 收起状态改为固定 124dp 的右侧窄控制列；控制列只在右下角放置 112dp 吉祥物按钮，业务内容与控制列是同一个 `Row` 的相邻区域，因此不存在覆盖。
- 控制列不绘制大面积底色或底部横条，视觉上只出现右下角吉祥物。
- 展开状态用现有停靠分栏替换右侧窄控制列，保持业务区、分隔条和助手区宽度守恒。
- 展开助手继续支持 360–720dp 拖动调宽，业务区继续保留至少 640dp。
- 宽度计算先扣除 210dp 左侧导航：`dockWidth = windowContentWidth - 210dp`。
- 收起状态满足 `210dp + businessWidth + 124dp == windowContentWidth`。
- 展开状态满足 `210dp + businessWidth + 8dp + assistantWidth == windowContentWidth`。
- 只有 `dockWidth >= 640dp + 8dp + 360dp` 时才允许展开；阈值不再错误地应用于整个窗口。
- 窗口宽度不足时，点击吉祥物只在 124dp 控制列内、吉祥物上方显示稳定的紧凑提示，不改变当前左右布局，不在顶部工具栏、业务区或窗口底部创建提示层。

## 测试与验收

1. 顶部工具栏测试：设置存在并可路由；Logo、产品名、工作台、资料录入和运行记录都不在顶部工具栏。
2. 左侧导航测试：三个业务入口存在、选中状态正确、点击回传 canonical destination；设置不在左侧。
3. 收起布局测试：不再存在横跨业务区的底部安全区；断言 `navigationWidth + businessWidth + collapsedControlWidth == contentWidth`；吉祥物位于控制列右下且不与表单保存/提交按钮相交。
4. 展开布局测试：左侧导航保持可见；断言 `navigationWidth + businessWidth + dividerWidth + assistantWidth == contentWidth`；展开阈值按扣除导航后的 `dockWidth` 计算；拖动和再次收起行为保持正确。
5. 宽度不足测试：提示节点只能位于右侧 124dp 控制列内并在吉祥物上方，不与业务区、顶部工具栏或吉祥物相交。
6. 品牌测试：应用内容区不再渲染第二套 Logo/产品名，原生窗口标题与安装包品牌保持不变。
7. 运行聚焦 Compose 测试、业务桌面全量测试，并用独立前后端真实窗口复验最大化、左右导航、设置入口和助手收起/展开。

## 非目标

- 不改业务表单字段和业务接口。
- 不改 Provider 设置功能本身。
- 不改 Windows 原生标题栏和安装包产品名。
- 不引入浮层式助手，也不让吉祥物覆盖业务内容。
